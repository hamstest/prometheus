# 身体・意味・動作の知識

V3単独で動く小さなオントロジーと版付きの動作定義。旧V1の概念辞書、構造の取得・抽出・合成という考え方を、V3の固定クリップと共通の曲線計算へ接続した。

## 使い方

チャットで「頭を下げる・戻すの基本操作から一回うなずく動作を作り、それを二回使って返事を作って」と依頼する。エージェントは基本操作を意味検索し、要求して構成・条件を読み、中間動作を作る。中間動作のrefを再び確認して、wholeやelement-Nを次の合成に使える。最終候補とその制作に必要な中間動作だけを一括保存し、実モデルで試演する。「動作を調べて組み立てた記録」に検索・確認・合成・保存の経路が残る。

基本操作は22件。左右の腕の上げ・手振り・下ろし・開いて示す・戻し・保持、頭の下げ・戻し・左右向き・正面復帰・傾け・戻し、体幹の前傾・復帰を用意した。いずれも終了姿勢を保持し、復帰は別の操作で指定する。動作別の実行コードではなく、共通形式のクリップである。

画面の「身体・意味・部品の知識」から「基本操作」で絞って検索し、使う全体や部品を追加する。「組み立てて部品として保存」で名前と意味のある中間動作を作り、再びその全体や一部を材料にできる。「構成を一段下までたどる」で元の部品を開き、基本操作まで繰り返し遡れる。従来の見本には制作時の区間分解があり、新しい多段合成には各段の固定参照と配置が残る。未知の動作から基本操作を推測して捏造しない。

モーション画面では、動作を選び「意味・分解・部品を開く」。全体、準備、主動作、戻し、体幹、頭と首、左右の腕と手を部品として追加できる。別の動作へ切り替えても部品列は保持する。「編集案を作る」の後、通常の試演・保存を使う。同時合成は各部品の長さを速度倍率で揃える。例えば3.15秒の腕と1.4秒の頭なら、腕を1倍、頭を1.4/3.15倍にすると揃う。

## 正本と関係

- `ontology.ts`：安定ID、表示名、別名、意図／動作／段階の分類、`isA`、`relatedTo`、身体と骨の`partOf`。身体の座標、編集範囲、腕を協調単位として扱う理由も返す。
- `knowledge` SQLiteテーブル：動作ID・版・SHA-256に結び付く定義の不変revision。概念、場面・条件、各部品の時間範囲・使用部位・前提・期待される働きを保持する。旧revisionは残る。
- `knowledge-inspect`：動作と部品の`partOf / usesBodyPart / intendedMeaning / describedAs`、構成の`usesVersion`、派生の`derivedFrom`を返す。人の評価は従来の版・身体・場面に限定した別記録。
- `Motion.derivation`：使った動作版・知識revision・部品キー・速度・変位倍率・合成方法・出力上の配置（layout）と条件。layoutからelement-Nを定義し、基本操作／合成動作／表現を同じ形式で何段も再利用する。保存時に参照・ハッシュ・配置を検査する。直接曲線を編集した場合も制作時の由来として残る。

現在の辞書は`prometheus-body-behavior-4`。旧revisionには旧辞書IDを保持する。「さようなら」は別れの挨拶、「お礼」は感謝へ対応する。上位概念の「対話表現」は下位の同意・説明なども見つける。関連だけの候補は`includeRelated:true`で広げる。`concepts`の明示条件はAND。自然文では別名、上位関係、日本語の語分割を使って候補を順位付けする。基本操作は`abstraction:"primitive"`、中間動作は`motion`、表現は`expression`で絞れる。意図全体の適切さはエージェントと人が判断する。

制作済み見本と内容が一致する固定版には、制作時の準備・主動作・戻しを定義する。ユーザーが変更した見本へ元の段階を自動適用しない。未知のクリップは意味タグの辞書照合と全区間・部位の構造を提示し、時間的な意味の分解は`knowledge-define`で定義する。構成は既存の使用箇所を取得できる。

## 操作例

すべて`POST /api/{operation}`、MCPでは`motion_{operation}`。`knowledge-search`は最大8件・3,600 UTF-8バイト以内の`{key,description}`だけを返す。keyはID@版。構成・条件は`knowledge-inspect`を要求したときだけ、曲線の数値は`motion-parameters`を要求したときだけ取得する。画面用の`search`は最大50件の部品付き結果を返す。

```json
{"query":"頭を下げる","abstraction":"primitive","limit":8}
```

`knowledge-search`の結果を`knowledge-inspect`へ渡す。

```json
{"ref":{"id":"primitive.head.down","version":1}}
```

次はこの作業環境で確認した`derive`入力。新しいDBでは見本の版が1の場合もあるため、検索結果の版に合わせる。

```json
{
  "name":"右手を振りながら小さくうなずく挨拶",
  "meanings":["挨拶","うなずく"],
  "mode":"parallel",
  "selections":[
    {"ref":{"id":"greeting","version":2},"revision":1,"component":"body-rightArm","speed":1},
    {"ref":{"id":"acknowledge","version":1},"revision":1,"component":"body-head","speed":0.4444444444444444}
  ]
}
```

`derive`は未保存の`motion`と条件を返す。単一部品の抽出も`mode:"sequence"`と1要素の`selections`で行う。保存・試演は従来の`save / play`。定義の編集は`knowledge-define {ref,expectedRevision,definition}`。定義の入力形式はcapabilitiesのJSON Schemaとinspectの出力を参照する。

数値確認を要求する例：`motion-parameters {ref,revision,component:"whole",channels:["head.x"],limit:20}`。部品区間内の曲線境界の位置・速度・加速度と次ページoffsetを返す。指定したチャンネルだけを取得し、speed（0.25〜3倍）とamplitude（0.1〜2倍、開始姿勢を基準とする変位）の変更範囲も分かる。振幅を下げた戻しは元へ戻り切らないため、往復全体を調整するなど端点の意味を確認する。

## 合成と検証の範囲

抽出端では元の曲線の位置・速度・加速度を評価し、内部の区切りも保持する。速度倍率rで時間を1/r、速度をr、加速度をr²にする。順次合成は共通接続方式を使い、各部品が操作しない部位は直前の終端姿勢を保持する。たとえば腕を上げてから頭を下げても腕は下がらない。同時合成は同じ長さの異なる部位だけを重ねる。所有部位の和だけを出力し、合成結果を次に使っても不要な部位を占有しない。結果は普通のClipであり、再生時の再帰実行器はない。

最大12部品、派生クリップ120秒、速度0.25〜3倍。同じ関節の所有競合、長さの不一致、曲線範囲の逸脱、存在しない知識の版・部品は拒否する。肩・上腕・前腕・手首を腕の一組として抽出する。手指の個別駆動・下半身は現行プロファイルの対象外。

条件・効果は由来付きの説明であり、汎用論理ソルバーによる前後条件の証明ではない。部位を切り離すと体幹との協調や掌の世界方向が変わり得る。数値検証と、意図・自然さ・衣服や腕の干渉の評価を混同しない。合成の意味は新しい仮説として明示し、子の採用評価を継承しない。

会話エージェントは最大24判断で反応の必要性・検索・定義取得・数値取得・派生を要求できる。初回カタログは空で、文章・表情・身体動作のどれが必要かを先に判断する。動作が必要なら短い意味で検索し、0件なら部位・順序に分解して基本操作や意味付き操作を探して組み立てる。通常会話へ候補を送らない。検索結果にはIDと短い説明だけを渡し、編集用の入力仕様も定義取得後に渡す。会話で試した固定refはassociatedMotionとして履歴へ付け、「それを」などの修正で参照できる。

中間案は会話要求ごとのメモリDBに置く。最終案から到達する中間案だけを、固定参照と知識revisionを保って本DBへ一括保存する。別の案、失敗した要求、中止した応答はモーション資産を残さない。保存競合時は途中で追加した中間案もロールバックする。参照展開は深さ16・512固定版以内。外部MCPでは`derive → save → knowledge-inspect`を繰り返すことで同じ階層を作れる。
# 意味付き操作の追加（2026-09-10）

基本操作には、固定曲線に加えて、方向・角度・時間／平均角速度から生成する6種類の定義を追加した。`semantic-search`はIDと説明のみ、`semantic-inspect`は選択した操作の意味・単位・範囲、`semantic-build`は通常クリップを返す。詳細は[意味付き操作](semantic-operations.md)。オントロジー第3版では前腕／上腕のひねりを「腕をひねる」の下位概念として定義し、生成結果から操作定義へ`instantiates`、開始姿勢の固定版へ`usesPose`を結ぶ。保存済みの曲線・旧知識版は保持する。

## 両手の協調部品と確認（2026-09-11）

第4版では、胸の前に両手を構える・手のひらを近づける・間を開くという意味を追加した。基本曲線はこれらと下ろす操作の4件（`primitive.hands.ready / close / open / lower`）。いずれも両腕を一緒に所有する汎用部品で、close/openを順番に繰り返し、前後にready/lowerを置ける。同時合成で同じ腕の別部品を重ねない。手のひらの中心は手首と中指付け根の中点で測り、openは約20cm、closeは約1.2cmの間隔を持つ。表面メッシュの衝突判定ではない。

生成した意味は候補として提示する。生成元を持つ保存動作も、その固定版・身体・場面で最新の採用記録がacceptedでなければ再試演時に確認を求める。会話の「いいね」から採用記録を自動生成することはない。
